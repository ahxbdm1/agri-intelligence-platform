# 需求分析说明书

参赛队伍：云穗智擎（山东建筑大学 计算机与人工智能学院）　队长：张衡　指导教师：刘新锋

## 一 项目范围

《农智云瞰》参加山东省大学生软件设计大赛大数据与人工智能行业应用开发赛道，面向县域农业主管部门、农技站、合作社和种植大户，服务于病虫害监测、产量风险管理、巡检调度和农情报告编制。系统以山东省济宁市鱼台县为示范县域，以乡镇和农田地块为基本管理单元，汇集气象、传感器、田间踏查、测产、病虫害上报和处置记录，形成从数据治理、风险挖掘到任务闭环的辅助决策工具。

系统的数据分为两层：大数据明细层承载百万级原始观测记录，由 Spark 离线链路完成清洗、关联与聚合；在线业务层只承载分析产出与业务操作记录，服务页面查询。两层的单向关系是本系统区别于普通业务系统的核心约束。

本版本为竞赛演示和工程验证版本，业务数据由固定随机种子脚本按真实气候与农事规律生成，图像模型基于公开数据集训练。系统输出用于辅助研判，不替代农技专家的现场诊断和用药决定。

## 二 用户角色

| 角色 | 使用目标 | 主要权限 |
| --- | --- | --- |
| 县域管理员 | 掌握全县风险态势并调度资源 | 查看全局数据、预警、巡检、报告和数据管理功能 |
| 农技专家 | 复核识别结果并提出处置建议 | 查看地块详情、模型解释、识别结果、问答和任务记录 |

## 三 业务需求

### 0 大数据与人工智能行业应用开发需求（赛道核心）

赛道命题要求作品体现大数据与人工智能在行业中的实际应用。团队据此为自己设定了以下技术目标，用于支撑真实行业应用而非演示玩具。

> 注：以下为团队自定指标，**不代表本届通知的强制门槛**；通知的具体约束以官网原文为准。

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| BD-1 | 明细层数据规模达到百万级 | 造数脚本对总量做断言，不足 100 万条直接失败退出；实测 1,591,545 条 |
| BD-2 | 离线分析由 Spark 承担 | 清洗、关联、窗口计算、聚合全部使用 Spark SQL / DataFrame，业务库不参与明细计算 |
| BD-3 | 数据按数仓分层组织 | 落地 ODS / DWD / DWS / ADS 四层，各层可独立查看中间结果 |
| BD-4 | 数据治理可度量 | 逐表统计去重量、越界量、缺失剔除量与保留量，输出数据质量报告 |
| BD-5 | 支持 Hive 表注册 | 提供四层外部表 DDL，可在 Hive Metastore 环境注册并用 SQL 访问 |
| BD-6 | 分析口径可复核 | 提供同口径参考实现与逐字段比对脚本，结果差异容差 0.02 |
| BD-7 | 结果可完全复现 | 固定随机种子，两次生成的行数、文件数与体积一致 |

### 1 农情总览

系统应按县域汇总种植面积、地块数量、高风险地块、近期病虫害上报、预测减产风险、识别模型指标和预警处理率，并提供风险趋势、作物结构、乡镇风险排名和最新预警。

### 2 地图风险监测

系统应在县域模拟地图上展示地块位置和边界，按低、中、高、极高风险区分颜色。用户可按乡镇、作物和风险等级筛选，点击地块后查看面积、作物、风险因素、天气摘要和建议巡检时间。

### 3 病虫害识别

用户可拖拽或选择叶片图片。系统调用可替换的视觉模型，返回病虫害名称、置信度、严重度、防治建议和人工复核标志，并展示疑似病斑区域说明。模型不可用时，接口应返回结构化的 Mock 结果并标明实际模式。

### 4 风险与产量预测

用户选择作物、乡镇和时间范围后，系统应返回风险趋势、产量预测、模型误差指标、特征贡献和处置建议。预测结果应能追溯模型版本与数据集版本。

### 5 预警与巡检

系统应展示预警等级、触发原因、负责人、处理建议和处理状态。用户可以修改状态，并根据预警一键生成巡检任务。任务包括地块、优先级、截止时间、负责人、描述和处理记录，支持新增、编辑和状态更新。

### 6 AI 农技助手

系统应基于本地 Markdown 知识库进行检索，并优先调用已配置的 RAGFlow。回答应显示引用来源、远程或本地模式、实时风险数据摘要和建议操作。远程服务不可用时必须自动降级，不能阻断核心业务。

### 7 数据和报告

数据管理支持 CSV 导入和数据导出。报告页面支持生成县域农情风险日报，内容包括核心指标、风险地块、模型预测和处置建议，可导出 Markdown 或 HTML。

## 四 非功能需求

1. 可用性：核心页面在演示数据完整时可正常访问，接口异常时返回明确错误信息。
2. 性能：常规列表和汇总接口在本地演示数据规模下应保持秒级响应；RAGFlow 问答允许因远程检索和生成产生十几秒延迟。
3. 可维护性：前后端分离，模型、知识库、批处理和业务服务分别组织，模型接口保持稳定。
4. 可部署性：支持 SQLite 本地运行和 Docker Compose 部署 PostgreSQL、后端及前端。
5. 安全性：使用 JWT 进行登录认证，API Key 仅从环境变量读取，日志不输出密钥和密码。
6. 可解释性：风险模型返回主要影响因素，识别模型返回置信度、严重度和疑似区域说明。

## 五 业务流程

数据采集或导入后，系统先完成字段校验、类型转换和异常标记，再写入业务数据库。批处理任务按乡镇和作物聚合，计算风险排名、未来趋势、产量预测和巡检优先级。在线页面调用汇总接口和模型接口形成可视化结果；达到风险阈值后生成预警，管理员派发巡检任务，现场人员反馈处理记录，最终在日报中归档。

## 六 验收要点

验收分为两部分。

**大数据链路验收**：明细层总量达到百万级（实测 1,591,545 条）；Spark ETL 四层全部产出且行数可核对；数据质量报告完整；Spark 产出与参考实现逐字段一致；固定种子两次生成结果完全一致。

**在线系统验收**：覆盖登录、Dashboard、地图筛选、图片识别、风险和产量预测、预警状态变更、巡检 CRUD、AI 问答引用、CSV 导入导出、日报生成及 Docker 启动。业务库演示数据应满足 6 个乡镇、80 个地块与完整的预警、巡检记录。

**非功能验收补充**：在双核环境下，明细层生成约 35 秒完成；分析层查询响应保持秒级；评审期内作品地址与备用地址须持续可访问。
