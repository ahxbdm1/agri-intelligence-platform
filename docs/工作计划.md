## 一 计划目标

围绕山东省大学生软件设计大赛“大数据与人工智能行业应用开发”赛道命题，完成从需求分析、数据湖构建、Spark 分析链路、模型训练、系统开发、测试部署到材料整理的完整项目过程。计划采用阶段交付方式，每个阶段形成可检查的代码、数据或文档成果。团队为自己设定了「明细数据达到百万级、离线分析由 Spark 承担」的技术目标，以支撑真实行业应用而非演示玩具，因此第 2、3 阶段为整个计划的重心。

## 四 风险控制

数据规模与技术栈是团队自设的技术目标，因此在造数脚本中内置总量断言、在 Spark 作业中输出运行报告，使达成情况随时可验证。另立一条纪律：赛道名称、材料清单与时长限制一律以本届官网通知原文为准，不得依据往届页面或相近赛道推断。视觉模型数据不足时，优先保证统一接口和可替换训练脚本，并在材料中如实说明验证边界。远程 RAGFlow 不稳定时保留本地知识库降级。Spark 环境统一走 Docker，规避 Windows 下 Hadoop winutils 依赖。正式提交前必须在录制视频的机器上重新执行造数、ETL、口径校验、训练与核心流程，避免只在开发机验证。
