## 一、本地部署

### 1. 环境要求

- Node.js 20 或以上
- Python 3.11 或以上；Windows 推荐使用 `py -3`
- 可选：Docker Desktop
- 可选：PostgreSQL 16；不安装时默认使用 SQLite

### 2. 创建隔离环境并安装后端依赖

```powershell
cd <项目根目录>
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

推荐使用独立 Python 3.11 环境，避免与全局的 NumPy / SciPy / scikit-learn 版本冲突。

### 3. 安装前端依赖

```powershell
cd frontend
npm install
```

### 4. 初始化演示数据

```powershell
cd ..
.\.venv\Scripts\python.exe scripts/generate_demo_data.py
.\.venv\Scripts\python.exe scripts/train_models.py
.\.venv\Scripts\python.exe backend/ml/train/train_disease_model.py
```

如需启用 YOLO 病斑检测模型，先安装 CUDA 版 PyTorch 和 YOLO 依赖：

```powershell
\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
\.venv\Scripts\python.exe -m pip install -r backend/requirements-yolo.txt
```

如果只验证合成数据训练链路，可执行：

```powershell
\.venv\Scripts\python.exe backend/ml/train/train_yolo_disease_model.py
```

正式演示使用公开真实图像训练入口：

```powershell
\.venv\Scripts\python.exe backend/ml/train/train_yolo_plantdoc_model.py
```

该脚本读取 PlantDoc Object Detection Dataset 的 XML 框标注，生成 YOLO 数据集并训练 29 类病害检测模型。当前已训练权重为 `data/generated/models/plantdoc_yolo_best.pt`，验证指标见同目录下的 `plantdoc_yolo_best.metrics.json`。当前验证集结果为 mAP50=0.6542、mAP50-95=0.5212、Precision=0.6068、Recall=0.6151。指标来自公开数据，不代表山东本地田间泛化能力，正式应用前必须增加本地标注数据复测。

训练完成后在 `.env` 中设置 `DISEASE_MODEL_PROVIDER=yolo`、`MOCK_DISEASE_MODEL=false`，重启后端即可调用 PlantDoc 权重。PlantDoc 数据集按 CC BY 4.0 使用并在提交材料中保留来源和引用说明。

### 5. 启动后端

```powershell
$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --host 0.0.0.0 --port 8000 --reload
```

### 6. 启动前端

```powershell
cd frontend
npm run dev
```

访问 `http://localhost:3000`，API 文档访问 `http://localhost:8000/docs`。

## 一点五、大数据分析链路（赛道核心，必跑）

在线系统与大数据链路相互独立，可分别启停。**评审复现建议先跑本节，再跑在线系统。**

### 1. 生成大数据明细层

```powershell
.\.venv\Scripts\python.exe scripts/generate_bigdata_layer.py
```

固定随机种子，双核环境实测约 35 秒完成，生成 1,591,545 条明细记录，落盘到 `data/lake/ods/`，共 438 个分区文件、39.0 MB。脚本对记录总量做断言，不足 100 万条会直接以非零退出码失败。

可选参数：`--months` 调整时间跨度（默认 24 个月）、`--end` 调整截止日期（默认 2026-08-31）、`--scout-per-day` 调整每日踏查记录数、`--out` 调整数据湖根目录。

### 2. 运行 Spark ETL 主链路

推荐使用 Docker，可免除 Windows 下 Hadoop winutils 的环境依赖：

```powershell
# 方式一：单容器本地模式，一条命令跑完整链路（推荐评委复现使用）
docker compose -f docker-compose.bigdata.yml run --rm spark-local

# 方式二：起 Standalone 集群后提交作业，可在 http://localhost:8080 观察 Spark UI
docker compose -f docker-compose.bigdata.yml up -d spark-master spark-worker
docker compose -f docker-compose.bigdata.yml run --rm spark-submit
```

若本机已配置 Spark 环境，也可直接提交：

```powershell
spark-submit --master local[*] --driver-memory 4g `
  batch_jobs/spark_jobs/agri_etl_pipeline.py --lake data/lake
```

作业产出：`data/lake/dwd/`、`data/lake/dws/`、`data/lake/ads/` 三层结果，以及 `data/lake/_run_report.json` 运行报告（含各层行数、逐表数据质量与阶段耗时）。

### 3. 校验分析口径

```powershell
.\.venv\Scripts\python.exe batch_jobs/pandas_jobs/ads_reference_job.py
.\.venv\Scripts\python.exe scripts/compare_ads_outputs.py
```

参考实现与 Spark 主链路读同一份 ODS 数据、用同一套清洗规则与评分公式，比对脚本逐表逐字段校验，输出"完全一致"即通过。

### 4. 可选：注册 Hive 外部表

在具备 Hive Metastore 的环境中执行，将四层注册为外部表：

```bash
hive -f batch_jobs/spark_jobs/hive_ddl.sql   # 先把脚本中的 ${LAKE} 替换为数据湖根路径
```

## 二、Docker 部署

```bash
cp .env.example .env
docker compose up --build
```

服务器部署可使用 `docker-compose.server.yml` 覆盖配置。默认前端端口为 3001，后端 API 端口为 8003，访问地址为 `http://服务器公网IP:3001`，Swagger 地址为 `http://服务器公网IP:8003/docs`。若服务器安全组启用了端口白名单，需要放行 TCP 3001 和 TCP 8003。

Docker Compose 包含 PostgreSQL、FastAPI 后端和 Next.js 前端。默认 `SEED_DEMO_DATA_ON_STARTUP=true` 时，后端只会在数据库为空时自动生成演示数据；已有数据库不会被覆盖。生产环境关闭该变量后，首次初始化请手动执行：

```bash
python scripts/generate_demo_data.py
python scripts/train_models.py
```

如需本地 SQLite 演示，可不启动 PostgreSQL，直接使用本地部署方式。

## 三、环境变量

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | 数据库连接，默认 `sqlite:///./agri_intelligence.db` |
| `SECRET_KEY` | JWT 签名密钥，生产环境必须更换 |
| `FRONTEND_ORIGIN` | 前端跨域来源 |
| `NEXT_PUBLIC_API_BASE_URL` | 前端访问后端 API 地址 |
| `MOCK_DISEASE_MODEL` | 是否启用 mock 病虫害识别模型 |
| `DISEASE_MODEL_PROVIDER` | 病虫害模型类型：`rf`、`yolo` |
| `SEED_DEMO_DATA_ON_STARTUP` | 空数据库是否自动生成演示数据；生产环境建议关闭 |
| `OPENAI_API_KEY`/`DEEPSEEK_API_KEY`/`QWEN_API_KEY` | 可选大模型 API 配置 |
| `RAGFLOW_ENABLED` | 是否启用 RAGFlow 远程知识库 |
| `RAGFLOW_BASE_URL` | RAGFlow 服务地址 |
| `RAGFLOW_API_KEY` | RAGFlow API Key，仅写入 `.env` |
| `RAGFLOW_DATASET_IDS` | 农业知识库 ID，多个值用逗号分隔 |
| `RAGFLOW_CHAT_ID` | 绑定农业知识库的聊天助手 ID |
| `RAGFLOW_TIMEOUT_SECONDS` | 远程问答超时秒数 |
| `RAGFLOW_STATUS_TIMEOUT_SECONDS` | RAGFlow 配置状态查询超时秒数 |
| `AGRI_DEMO_BASE_DATE` | 演示数据基准日期；固定该值可复现实验结果 |

大数据链路不依赖环境变量，全部参数通过命令行传入，便于在容器中固定复现。

## 四、模型训练

风险评分、产量预测和异常检测模型可通过以下命令训练：

```powershell
.\.venv\Scripts\python.exe scripts/train_models.py
```

模型保存到 `data/generated/models/`。病虫害训练脚本使用固定种子生成合成叶片样本，输出 accuracy、precision、recall、F1 和混淆矩阵；这组指标只用于验证工程链路，不代表真实田间泛化能力。训练后将 `.env` 中 `MOCK_DISEASE_MODEL=false`，即可通过同一 API 调用训练模型。真实模型替换时保持 `backend/ml/disease_classifier.py` 的 `PestDiseaseClassifier.predict(image_bytes)` 返回结构不变即可。

YOLO 训练脚本同时保留合成数据链路和 PlantDoc 真实数据链路。默认接口调用 `plantdoc_yolo_best.pt`；合成模型只用于离线工程回归测试，PlantDoc 指标也不能替代本地田间验证。

## 五、常见问题

1. 登录失败：请确认已运行 `.venv\Scripts\python.exe scripts/generate_demo_data.py`。
2. 前端请求 401：清除浏览器 localStorage 后重新登录。
3. 地图底图未显示：外网瓦片可能受网络影响，地块 polygon 与风险颜色仍可显示。
4. Windows 下 `python` 是 2.7：请使用 `py -3`。
5. Docker 后端无数据：需要在目标数据库上执行初始化脚本。
6. 助手显示“本地降级”：访问 `/api/assistant/status` 检查配置对象，再查看回答中的 `warning`；不能仅凭有答案就判断 RAGFlow 正常。
7. RAGFlow 超时：远程问答默认等待 35 秒，适配检索与模型生成耗时；超时后会自动降级到本地 TF-IDF，后续请求会重新尝试远程服务。
8. 识别仍显示 mock：确认已运行 `\.venv\Scripts\python.exe backend/ml/train/train_disease_model.py`，并将 `.env` 中 `MOCK_DISEASE_MODEL=false` 后重启后端。
