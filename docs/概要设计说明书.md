## 一 系统定位

农智云瞰是面向县域农业风险治理的大数据与人工智能行业应用开发系统，参加山东省大学生软件设计大赛大数据与人工智能行业应用开发赛道。系统把多源农情数据、离线大数据分析链路、机器学习模型和基层处置流程组织在同一平台中，重点解决数据分散难用、发现滞后、研判缺乏量化依据和资源调度无据可依的问题。

系统的基本设计约束是：**百万级明细数据只在大数据链路中流动，在线业务库只消费分析产出**。这一约束决定了下面的分层与数据流设计。

## 二 总体架构

系统由离线分析链路与在线服务链路组成。

**离线分析链路**以 Apache Spark 为计算引擎，数据湖按 ODS / DWD / DWS / ADS 四层组织：ODS 为分区 gzip CSV 贴源层，DWD 为 Parquet + Snappy 明细清洗层，DWS 为地块-日风险特征宽表，ADS 为应用结果层。可选在 Hive Metastore 中将四层注册为外部表，供 Spark SQL、Hive CLI 与 BI 工具共用口径。

**在线服务链路**采用前后端分离架构。浏览器端由 Next.js 和 TypeScript 实现，负责路由、页面状态、图表、地图和交互；后端由 FastAPI 提供 RESTful API 和 Swagger 文档；SQLAlchemy 负责数据库访问，PostgreSQL 用于容器化部署，SQLite 用于单机降级。模型服务与 RAGFlow 客户端作为后端外部能力接入。

数据流向为：

```
多源采集 → ODS 贴源 → [Spark] 清洗去重 → DWD → [Spark] 两级汇聚 + 窗口特征 → DWS
        → [Spark SQL] 风险评分与聚合 → ADS → 业务库 → API → 驾驶舱/地图/预警/报告
                                                          ↑
                                          在线模型：检测 / 预测 / 异常 / RAG
                                                          ↓
                                             巡检反馈与处置记录回写业务库
```

明细数据不回流业务库，业务操作记录不参与明细计算，两条链路的耦合点只有 ADS 结果表。

## 三 功能分层

| 层次 | 主要模块 | 设计职责 |
| --- | --- | --- |
| 展示层 | 登录、驾驶舱、地图、识别、预测、预警、巡检、助手、报告 | 面向三类用户提供信息查看和业务操作 |
| 接口层 | auth、dashboard、farms、disease、predictions、alerts、inspections、assistant、reports | 认证、参数校验、错误转换和响应结构 |
| 业务层 | 风险计算、报告服务、RAGFlow 客户端、本地检索器、模型服务 | 编排数据、模型和处置逻辑 |
| 数据层 | SQLAlchemy、SQLite/PostgreSQL、CSV、Markdown 知识库 | 保存业务数据、模型指标和知识文档 |
| 大数据层 | Spark ETL 主链路、Hive 四层外部表、数据湖分区存储 | 明细清洗、质量度量、多源关联、窗口特征、风险评分与应用层聚合 |
| 模型层 | RandomForest、IsolationForest、YOLO 检测接口、RAG 检索 | 训练、评估、在线预测、异常检测与知识问答 |

## 四 部署结构

部署分为两套互不影响、可分别启停的 Compose 编排：

- `docker-compose.yml`：PostgreSQL + FastAPI + Next.js，承载在线业务。后端通过环境变量获得数据库连接与可选 RAGFlow 配置，前端通过 `NEXT_PUBLIC_API_BASE_URL` 访问后端。
- `docker-compose.bigdata.yml`：Spark Master + Worker + 作业提交入口，承载离线分析。另提供 `spark-local` 单容器模式，评委可一键复现完整链路，无需在 Windows 上配置 Hadoop winutils。

服务器部署用 `docker-compose.server.yml` 覆盖端口与数据目录。离线或轻量环境可直接使用 SQLite、本地 Markdown 检索和 Mock 视觉模型。

## 五 关键设计

1. 模型可替换：病虫害识别统一返回病害名称、置信度、严重度、防治建议和复核标志，Mock、轻量模型和 YOLO 可切换。
2. 远程优先、故障降级：RAGFlow 可用时返回远程答案和引用；超时或服务不可用时切换本地 TF-IDF，接口保留 warning。
3. 结果可追溯：风险和产量预测保存模型版本、数据集版本与指标，报告记录生成时间和数据截止日期。
4. 业务闭环：风险结果可以生成预警，预警可以生成巡检任务，任务记录又能反哺后续研判。
5. 口径单一来源：风险评分公式与分级阈值集中定义为常量，Spark 主链路与 pandas 参考实现共用同一套口径，并由比对脚本逐字段校验，杜绝"两处代码两套算法"。
6. 分层解耦：明细层的表结构即真实数据的接入契约，更换数据源不影响 DWD 以下任何一层。

## 六 外部接口

系统提供 `/docs` Swagger 页面。认证、Dashboard、地块、识别、预测、预警、巡检、助手、数据和报告接口均以 `/api` 开头，使用 JSON 传输；图片识别采用 multipart 文件上传，数据导入采用 CSV 文件上传。

## 七 非功能设计

通过统一请求日志、异常处理中间件、Pydantic 参数模型和 API 状态码保证可诊断性。前端对请求提供加载、错误和空状态，对移动端使用响应式布局。生产部署时应启用 HTTPS、限制 CORS、轮换密钥并配置数据库备份。
