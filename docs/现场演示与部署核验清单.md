# 现场演示与部署核验清单

参赛队伍：云穗智擎（山东建筑大学 计算机与人工智能学院）　队长：张衡　指导教师：刘新锋

## 一、推荐演示环境

### 方案 A：现场电脑本地演示

- Windows 10/11 或 Ubuntu 22.04。
- Python 3.11 独立虚拟环境。
- Node.js 20 或项目要求的兼容版本。
- 浏览器使用 Edge 或 Chrome 最新稳定版。
- 预留 8GB 以上内存、20GB 以上磁盘空间（数据湖明细层与 Parquet 中间结果需要额外空间）。
- 安装 Docker Desktop，用于运行 Spark 大数据链路（免除 Windows 下 Hadoop winutils 依赖）。
- 演示前准备离线数据、模型文件和本地知识库，避免网络异常影响流程。

### 方案 B：服务器演示

- 推荐使用 2 vCPU、4GB 内存以上的 Linux 云服务器。
- 使用 Docker Compose 启动 PostgreSQL、FastAPI 和 Next.js。
- 前端通过反向代理暴露 HTTPS 地址，后端 API 不直接暴露数据库端口。
- RAGFlow 使用远程服务时，设置超时和本地知识库降级，保证断网仍可演示。

## 二、演示前一天

1. 重新生成大数据明细层并核对总量：`python scripts/generate_bigdata_layer.py`，确认输出 1,591,545 条、438 个分区文件。
2. 跑通 Spark ETL 主链路：`docker compose -f docker-compose.bigdata.yml run --rm spark-local`，保存 `data/lake/_run_report.json` 作为答辩证据。
3. 校验分析口径：`python batch_jobs/pandas_jobs/ads_reference_job.py` 后执行 `python scripts/compare_ads_outputs.py`，输出应为"完全一致"。
4. 重新生成业务库固定种子演示数据并检查数量。
5. 执行风险模型、产量模型、异常检测和病虫害模型训练脚本。
6. 运行后端 pytest、前端 lint 和 build。
7. 确认前端能登录，Dashboard、地图、识别、预测、助手、报告页面均能打开。
8. 确认 `/docs`、`/health`、`/api/assistant/status` 可访问。
9. 为地图瓦片、RAGFlow 和模型接口准备离线或降级方案。
10. 清理真实密钥、服务器密码、个人信息和临时日志，避免进入提交压缩包。

## 三、推荐现场演示顺序

按技术实质优先于视觉展示的原则编排，先讲数据链路与 AI 能力，再讲界面。**具体评分权重以本届通知为准**；若偏重展示效果，则相应加长界面演示段。

0. 数据链路（**先讲，占时最多**）：终端展示造数输出与 `ods_manifest.json`；跑 Spark 作业并展示 `_run_report.json` 的各层行数与清洗剔除量；打开 `ads_data_quality.json` 逐表核对；展示 `compare_ads_outputs.py` 的口径一致性结果。
1. 登录：选择县域管理员账号。
2. Dashboard：展示 KPI、县域风险地图、天气摘要和优先关注地块。
3. 调度工作流：点击“执行今日调度”，展示巡检队列和农资建议。
4. 地图：筛选高风险地块，点击地块展示因子、天气和巡检建议。
5. 病虫害识别：上传叶片图片，展示置信度、病斑区域和防治建议。
6. 预测：选择地块，展示风险评分、产量曲线、模型指标和因子贡献。
7. AI助手：提出农业问题，展示 RAGFlow 来源、系统风险上下文和建议操作。
8. 报告：生成农情日报并下载 Markdown 或 HTML。

## 四、必须现场确认的风险

| 风险 | 处理方式 |
| --- | --- |
| 本机科学计算库冲突 | 使用 Python 3.11 独立虚拟环境或 Docker，不使用系统 Python |
| Docker 不可用 | 提前准备本地启动脚本和已初始化 SQLite 数据库 |
| RAGFlow 不可用 | 使用本地 Markdown 知识库降级，现场明确说明 |
| 地图瓦片网络不稳定 | 预留地图截图或离线瓦片方案，核心风险数据仍来自接口 |
| 真实数据不能公开 | 只提交脱敏仿真数据和字段说明，不提交个人信息或生产敏感数据 |
| 模型文件缺失 | 提前训练并把模型文件或可重复训练脚本放入源代码包 |
| Spark 容器拉取失败 | 现场网络可能拉不到 bitnami/spark 镜像，提前 `docker pull` 并保留 `docker save` 的离线镜像包 |
| 数据湖体积过大 | 明细层 gzip 后 39MB，Parquet 中间结果另占数百 MB，演示机需预留空间；必要时先清理 `data/lake/dwd` 与 `dws` 再重跑 |
| 评委要求现场重跑 | 造数 35 秒、Spark 本地模式数分钟，可现场演示；若时间不够，出示 `_run_report.json` 与录屏 |

## 五、演示真实性边界

本项目的县域农情数据为固定随机种子生成的仿真数据，按鲁西南暖温带季风气候与农技规律建模，示范县域取山东省济宁市鱼台县的真实行政区划与坐标。答辩时应明确：

1. 明细数据为仿真数据，用于验证数据治理、分析链路与业务闭环，不能表述为真实生产数据；明细层的表结构即真实数据的接入契约，替换数据源后下游无需改动。
2. 病虫害识别模型使用公开数据集 PlantDoc 与 IP102 训练，所报 mAP50 等指标只代表其官方验证集/测试集结果，**不代表山东本地田间识别准确率**。
3. 风险分级阈值按本数据集分布标定，年际气候变化或换用真实数据后需重新标定。
4. 上线真实农业场景前需经过本地标注数据训练、跨季节现场验证与农技专家审核。
